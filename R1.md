# R1 — Подтверждённые баги (чистка от 2026-10-27)

Проверено чтением кода. Всё, что было фичей, дизайном, дублем или уже пофикшено — удалено.
Оставлены только воспроизводимые по коду проблемы. Номера строк примерные (файл уехал после правок) — верить именам методов/полей.

## 1. Клоны
- `ShadowCloneEntity.die()` не вызывает `super.die()` — флаг смерти/счётчики пропускаются.
- `CloneOwnerHurtByTargetGoal.canUse` / `CloneOwnerHurtTargetGoal.canUse` — только `isSpectator()`, без `isAlive()/isDeadOrDying()`.
- `CloneVariantEvents.onCloneTick` — водяной/грязевой `discard()` напрямую вместо `pop()/dispel()` — теряется лут/звук/частицы.
- `ShadowCloneJutsuAbility.hasLivingClones` — скан только 128 блоков вокруг; ушедший рабочий позволяет дублировать призыв. Там же AABB-проверка рабочего.

Удалено как не-баги: `copyAmmo` схлопывание (задокументированный дизайн), `1 HP`, медитация-бонусы, XP/дропы владельцу (дизайн `ShadowCloneEvents:49-66` + `canGatherLoot` уже гейтит), `DEFAULT_LIFETIME 500 vs Clay 600` (техника ставит своё время, раннего попа нет), `взрывные рабочие` (метка по бомбе в руке — дизайн), `onSyncedDataUpdated только CHIBI` (атрибуты синкаются ванилью).

## 2. Способности
- `AbstractBreathAbility.handleCost` — тап `TAP_COST` мимо `masteryCost`.
- `DoubleJumpAbility.handleCost` — проверка против `STAMINA_COST`, а `useStamina` умножает на `staminaCostMultiplier` — возможен уход в минус.
- `ChakraDashAbility` — списание в `handleCost`, в `performServer` `return` при стене/не-сервере без возврата — трата без эффекта.
- `SecondBreathAbility:99` — `mastery = 0.0f` захардкожен, слепота не масштабируется.
- `ChakraTransferAbility:87/113` — кастер платит `masteryCost(8)`, союзник получает raw `8` — создание чакры из скидки.

Удалено: `WaterWalk десинк` (не подтверждено), `NinjaData upkeep без кредита` (путь STOP уже пишет `recordMastery`, поведение согласовано).

## 3. Сеть (валидация пакетов — все подтверждены)
- `ServerAbilityChannelPacket.decode:52` — `values()[status]` без границ — краш/эксплойт чужим пакетом.
- `ServerAbilityActivatePacket:140/159` — `ModeBus.closeOthers` до `canStartToggle` — отменённый тоггл всё равно закрывает режимы.
- `ServerToggleAbilityDisabledPacket` — отключение канала только обнуляет флаг, без `performServer`/очистки.
- Клиентские `readUtf/readInt` без лимитов: `ServerFriendActionPacket`, `ClientboundSensing/OreSense/Reveal/Friends/SupplyChest`, `ServerJutsuCastingPacket` ключ/спам.
- Нет `spectator`-проверок: `ServerUnlockSkillPacket`, `ServerBuySkillPointsPacket`.

Удалено как дубли/шум: повторные `isClientSide` в этом разделе (см. §6), `orElseThrow` в командах (стиль, не краш).

## 4. Capability / NinjaData
- `substitutionLocation/substitutionDimension` — `@Sync`, но в `serializeNBT/deserializeNBT` не пишутся — теряются при релоге.
- `cooldownTickEvents` не очищается перед загрузкой — старые КД остаются.
- `marker/kamui` грузятся условно без сброса при отсутствии тегов.
- `new ResourceLocation()` на битом NBT (`markerDimension/kamuiReturnDimension`) — исключение без try/catch.
- `maxSubstitutions` — ни `@Sync`, ни NBT.
- `DisabledAbilityDataSyncTracker/ToggleAbilityDataSyncTracker` — `new HashSet<>(size)` с сетевым `size` — отрицательный крашит.

Удалено: `ticksPassed переполнение` (практически недостижимо), `isTechniqueDamage null-guard` (там `Optional.map/orElse`, NPE нет), `INinjaData nullable` (нормальный контракт), `areFriends false на себе` (корректно).

## 5. Дерево скиллов
- `ServerBuySkillPointsPacket:52` — `requested<=0 → wanted=affordable` обходит `MAX_PURCHASE`.
- `SW skilltree_auto STRONG → body_second_breath` — узла нет (битая ссылка).
- Классы `SecondBreath/WindStep/Amenominaka/AnimalPath/Rinbo/RinneSharingan` существуют, `ABILITY.register` для них нет (проверено grep по `NarutoAbilities`) — либо регистрировать, либо удалить классы/доку. `RinneSharingan` при этом уже используется скидкой `Amaterasu:88/Kagutsuchi:132`, т.е. полуподключён.

Удалено: `SkillTreeScreen tryUnlock/buyPoints/hit-test`, `Skill PUT без дублей`, `два родителя body_flow` — либо UX-мелочь, либо линтер проходит; `JutsuScreen:656 SecondBreath` — уже не актуально.

## 6. Додзюцу / события (только то, что реально без гарда)
- `KamuiEvents.onLivingHurt:110` — нет `isClientSide`, работает на обеих сторонах.
- `KamuiJutsuAbility.spitBack:400` — clear-before-validate — сущность может остаться в Камуи.
- `SixPathsModeAbility` — upkeep не восстанавливает `senin`-бонус после закрытия Риннегана.
- `Sharingan burnout` закрывает `Susanoo+Sharingan`, но не `RinneSharingan`.
- `RinneSharinganAbility extends Ability`, не `AbstractDojutsuAbility` — обходит правило одного глаза (при этом скидка уже работает — половинчатое состояние).

Удалено как уже пофикшенное: почти все «нет isCanceled/isClientSide» — в текущем коде гарды есть (`SharinganEvents:57-60`, `ChakraShield:31`, `ByakuganAdvanced:109`, `Senrigan:38/51`, `RinneganExtra:206`, `TechniqueMark`, `TaijutsuCombo:81` и др.). R1 писался до фиксов.
